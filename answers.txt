Q1:The container orchestrator's control plane (specifically the Swarm manager in Part 1 and the Kubernetes ReplicaSet controller in Part 3) started the replacement. It continuously monitors the cluster to ensure the actual number of running containers matches the desired replica count specified in the manifest, automatically creating a new copy whenever one is deleted.
Q2:Choose Docker Swarm for simplicity and built-in Docker integration without extra setup. Choose K3s instead of full Kubernetes when you need a lightweight, fast setup on a laptop or smaller environment, since full Kubernetes requires significantly more memory, storage, and configuration overhead meant for large-scale production systems.
Q3:Kubernetes replaces pods gradually rather than all at once, waiting for the new version 1.1 pods to become ready before terminating the old version 1.0 pods. Because the Service continuously routes traffic to whichever healthy pods are running, the website never goes down.
